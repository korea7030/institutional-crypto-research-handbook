- Eclipse 공격이 전역 합의 규칙을 바꾸지 않으면서도 피해자 관점의 체인 시야를 약화시키는 방식을 설명할 수 있다.
- reorg, stale block, 전파 지연 위험의 온체인 관측 징후를 식별할 수 있다.

## 3. Executive Summary

Bitcoin의 작업증명은 비용 기반 순서화 메커니즘이다. 과거 블록을 바꾸려면 그 블록의 작업을 다시 해야 하고, 이어지는 후속 블록들이 쌓아 올린 누적 작업량까지 따라잡아야 하므로 기록 재작성 비용이 커진다.[^ref-btc-wp] Bitcoin Core는 블록 헤더를 인코딩된 목표값과 대조해 검증하고, 가장 큰 누적 작업량을 가진 유효 체인을 선택함으로써 이를 구현한다.[^ref-btc-core-pow][^ref-btc-core-validation]

핵심 공격 모델은 "SHA-256을 깨는 것"이 아니다. 충분한 블록 생산 확률, 전파 우위, 또는 피해자의 네트워크 시야 통제를 통해 경쟁하는 유효한 대체 역사를 피해자가 기대한 역사보다 더 매력적으로 만드는 것이다.

고전적인 이중지불 공격은 경쟁(race)이다. 공격자는 공개 체인에서 상인에게 결제하는 한편, 동일한 코인을 자신에게 되돌리는 사설 대체 체인을 비공개로 채굴한다. 그 사설 체인이 공개 체인의 누적 작업량을 따라잡고 넘어선다면, 정직한 노드는 공격자의 유효한 대체 역사로 reorg할 수 있다.[^ref-btc-wp]

작업증명은 무효 코인을 생성하게 해주지 않는다. Nakamoto는 공격자가 노드로 하여금 무효 트랜잭션이나 무효 블록을 받아들이게 만들 수 없다고 명시한다. 공격자의 실질적인 목표는 자신의 최근 트랜잭션 순서나 포함 여부를 바꾸는 것이다.[^ref-btc-wp]

실무상 공격 모델은 다섯 가지 묶음으로 나눌 수 있다.

| Attack Model | Primary Goal | Main Resource | Core Risk |
|---|---|---|---|
| Double-spend reorg | 최근 결제 뒤집기 | 해시레이트와 시간 | 상대방 settlement finality 상실 |
| Majority attack | 최근 기록의 안정적 재작성 또는 검열 | 과반 또는 근과반 해시파워 | 체인 liveness 및 결제 리스크 |
| Selfish mining | 비례 해시 점유율 이상 수익 확보 | 해시파워와 전파 우위 | 마이닝 중앙화 압력 |
| Eclipse-assisted attack | 피해자 체인 시야 통제 | 네트워크 장악 자원 | 피해자별 가짜 최종성 |
| Difficulty/timestamp manipulation | 미래 채굴 조건 왜곡 | 조율된 마이닝 파워 | 블록 간격 및 난이도 불안정 |

분석가에게 중요한 구분은 전역 합의 리스크와 피해자 로컬 인식 리스크의 구분이다. 공개 reorg는 발생 후 전역적으로 관측 가능하다. 그러나 진행 중인 private fork는 직접 관측되지 않는다. 단일 피해자를 겨냥한 Eclipse 공격은, 그 피해자의 로컬 판단을 더 넓은 네트워크 시야와 비교하기 전까지는 공개 체인에서 보이지 않을 수 있다.

## 4. 원래 설계

Bitcoin 백서는 작업증명을 신뢰된 타임스탬프 기관 없이 기록을 순서화하는 메커니즘으로 제시한다. 원래 설명에서 "longest chain"은 가장 큰 작업증명 노력이 축적된 체인을 뜻한다.[^ref-btc-wp] 후대 구현과 문서는 이를 더 정밀하게 표현한다. 노드는 단순히 블록 수가 가장 많은 체인이 아니라, 가장 큰 누적 작업량을 가진 유효 체인을 따른다.[^ref-btc-dev-blockchain][^ref-btc-dev-operating]

보안 주장은 확률적이다. 정직한 채굴자가 협력하는 공격자 집단보다 더 많은 해시파워를 가진다면, 정직 체인은 공격자의 충돌 체인보다 더 빠르게 연장될 것으로 기대된다.[^ref-btc-wp] confirmation이 쌓일수록 공격자가 따라잡아야 할 작업량은 늘어난다.

원래 설계는 공격자의 힘에 중요한 제한도 둔다. 공격자가 더 빠르게 대체 체인을 생성하더라도, 정직한 노드는 여전히 트랜잭션과 블록을 검증한다. 공격자는 무에서 유를 창출할 수 없고, 적법한 승인 없이 코인을 쓸 수 없으며, 정직한 풀노드에게 무효 블록을 받아들이게 만들 수 없다.[^ref-btc-wp]

이로부터 다음과 같은 실용 모델이 나온다.

1. 합의 규칙이 어떤 블록이 유효한지 정의한다.
2. 작업증명은 경쟁하는 유효한 역사들 사이의 순서를 정한다.
3. 누적 작업량이 풀노드가 선택할 유효한 역사를 결정한다.
4. confirmation은 절대적 비가역성이 아니라 증가하는 대체 비용을 측정한다.
5. 적대자는 순서, 전파, 유인, 로컬 가시성을 공격한다.

## 5. 프로토콜 구조

### 방어 계층

Bitcoin의 PoW 보안은 여러 계층 위에 서 있다.

| Layer | Defensive Role | Attack Surface |
|---|---|---|
| Cryptographic hash function | 블록 탐색을 예측 불가능하게 만듦 | 실질적 해시 역산보다 ASIC 집중 |
| Target and difficulty rules | 기대 블록 간격을 정규화 | 타임스탬프 조작, 난이도 전이 엣지 케이스 |
| Cumulative chainwork | 가장 큰 작업량의 유효 체인 선택 | private fork 경쟁 |
| Full validation | 무효 블록과 트랜잭션 거부 | 노드 고립 또는 약한 클라이언트 가정 |
| Peer-to-peer relay | 블록과 트랜잭션 배포 | Eclipse, partition, 전파 우위 |
| Miner incentives | 정직한 체인 연장 보상 | Selfish Mining, withholding, 수수료 기반 reorg 유인 |

작업증명은 단일 보안 스위치가 아니다. 어떤 블록은 해시 목표값은 만족해도 트랜잭션, 머클 루트, 코인베이스, 버전, 컨텍스트 규칙을 위반하면 무효다.[^ref-btc-core-validation] 반대로 어떤 블록은 완전히 유효해도 다른 유효 브랜치가 더 많은 작업량을 쌓으면 체인 경쟁에서 질 수 있다.

### 공격 표면

PoW 공격은 보통 다음 중 하나 이상을 겨냥한다.

| Surface | Question |
|---|---|
| Hashrate share | 공격자가 경쟁할 만큼 빠르게 블록을 만들 수 있는가? |
| Time | 공격자가 경쟁을 얼마나 오래 지속할 수 있는가? |
| Confirmations | 공격자가 얼마나 많은 정직 작업량을 대체해야 하는가? |
| Propagation | 공격자가 채굴자가 먼저 보는 블록을 통제할 수 있는가? |
| Network view | 공격자가 피해자를 정직한 피어로부터 고립시킬 수 있는가? |
| Economic incentives | 공격이 정직 채굴보다 더 수익성 있는가? |
| Difficulty rules | 타임스탬프 또는 리타깃 동작을 악용할 수 있는가? |

### 실패 모드

| Failure Mode | Description | Global or Local |
|---|---|---|
| Public reorg | 기존에 수용된 브랜치가 더 큰 작업량 브랜치로 대체됨 | 전파 후 전역 |
| Private-fork success | 숨겨진 브랜치가 공개 브랜치를 추월함 | 공개 후 전역 |
| Censorship | 지배적 채굴자가 트랜잭션을 배제하거나 지연 | 지속되면 전역 |
| Stale-block increase | 더 많은 블록이 전파 경쟁에서 패배 | 전역적 징후 |
| Victim eclipse | 피해자가 공격자가 만든 네트워크 시야를 봄 | 비교 전까지 로컬 |
| Incentive deviation | 채굴자가 블록을 숨기거나 선별적으로 공개 | 일부 은닉됨 |

## 6. 기술적 메커니즘

### Model 1: Double-Spend Reorganization

이중지불 reorg는 네 단계로 전개된다.

1. 공격자가 피해자에게 지급하는 공개 트랜잭션을 만든다.
2. 피해자는 공개 체인에서 confirmation을 기다린다.
3. 공격자는 해당 결제를 제외하거나 대체하는 충돌 브랜치를 비공개로 채굴한다.
4. 사설 브랜치가 더 많은 작업량을 쌓으면 공격자는 이를 공개하고, 정직한 노드는 그쪽으로 reorg할 수 있다.

이 공격은 유효한 블록을 사용한다. 무효 트랜잭션이 필요하지 않다. 대체 비용이 경제적, 통계적으로 충분히 커지기 전까지 최근 체인 기록이 확률적이라는 사실을 이용한다.

백서의 시나리오는 발신자가 수신자에게 결제가 일어났다고 믿게 한 뒤, 나중에 자신에게 되돌아가는 대체 트랜잭션으로 바꾸는 형태다.[^ref-btc-wp]

### Model 2: Majority-Hashrate Attack

과반 해시레이트 공격자는 정직 체인보다 더 높은 기대 성장률을 가진다. 이 경우 확률적 공격은 모델 가정 아래에서 신뢰 가능한, 혹은 결국 성공하는 공격으로 바뀐다. 과반 해시파워를 가진 공격자는 다음을 시도할 수 있다.

- 자신의 최근 결제를 되돌리기
- 특정 트랜잭션을 포함하지 않음으로써 검열하기
- 정직한 채굴자가 찾은 블록을 orphan 처리하기
- settlement finality에 불안정성 만들기
- 사설 브랜치를 선택적으로 공개하기

하지만 공격자도 다음은 할 수 없다.

- 합의 보조금 및 수수료 규칙을 넘는 코인 생성
- 유효한 서명 없이 코인 사용
- 무효 스크립트를 유효하게 만들기
- 정직한 풀노드가 무효 블록을 받아들이게 만들기
- 필요한 대체 작업량 없이 과거 기록을 바꾸기

이 구분은 기관 리스크에서 중요하다. 과반 해시파워는 settlement ordering과 liveness를 위협하지만, 풀노드 검증 자체를 제거하지는 않는다.

### Model 3: Selfish Mining

Selfish Mining은 유인 공격이다. Selfish miner는 발견한 블록을 즉시 공개하지 않고 숨긴다. 정직한 채굴자는 공개 체인 위에서 계속 채굴하는 반면, Selfish miner는 비공개 브랜치를 연장한다. 공개 브랜치가 따라잡으려 할 때나, 공개 시 정직한 채굴 작업을 낭비시킬 수 있을 때 전략적으로 블록을 공개한다.[^ref-eyal-sirer]

Eyal과 Sirer의 모델은 Bitcoin 마이닝 프로토콜이 모든 네트워크 및 전파 가정 아래에서 항상 인센티브 정합적이지는 않다고 주장한다. 이 모델의 위험은 즉각적인 체인 재작성 자체만이 아니다. 어떤 채굴자나 풀이 자신의 해시 점유율 이상 수익을 얻을 수 있고, 이 때문에 전략적 withholding이 매력적이 되어 마이닝 집중이 강화될 수 있다는 점이다.[^ref-eyal-sirer]

Selfish Mining은 다음에 의존한다.

- 공격자 해시파워 점유율
- 블록 경쟁 시 전파 우위
- 정직한 채굴자의 동률 처리 방식
- 비공개 블록을 숨겨둘 수 있는 능력
- 더 높은 상대 수익이라는 경제적 보상

분석가 관점에서 Selfish Mining은 stale rate 상승, 의심스러운 시점의 블록 공개, 비정상적 orphan 패턴으로 나타날 수 있다. 하지만 비공개로 숨겨진 블록은 공개되기 전까지 보이지 않으므로, 공개 체인 데이터만으로 입증하기는 어렵다.

### Model 4: Eclipse-Assisted Attacks

Eclipse 공격은 피해자의 P2P 네트워크 시야를 겨냥한다. Heilman, Kendler, Zohar, Goldberg 논문은 적대자가 피해자 Bitcoin 노드로 들어오고 나가는 모든 연결을 독점하는 상황을 설명한다. 이렇게 고립되면 피해자는 공격자가 만든 블록과 트랜잭션 시야만 볼 수 있다.[^ref-heilman-eclipse]

이 공격은 PoW 공격을 세 가지 방식으로 증폭시킬 수 있다.

1. 피해자별 이중지불: 피해자는 더 넓은 네트워크가 동일하게 취급하지 않는 confirmation을 볼 수 있다.
2. 마이닝 교란: Eclipse된 채굴자는 stale 또는 적대적 브랜치 위에서 해시파워를 낭비할 수 있다.
3. 포크 조작: 피해자는 블록을 늦게 받거나 선택적으로 받거나 왜곡된 순서로 받을 수 있다.

Eclipse 공격이 자동으로 전역 체인 선택을 바꾸는 것은 아니다. 바뀌는 것은 피해자가 보는 체인 시야다. 소수 피어 또는 외부 호스팅 노드 인프라에 의존해 고액 의사결정을 하는 서비스일수록 위험이 크다.

### Model 5: Difficulty and Timestamp Manipulation

난이도 조정은 관측된 블록 시간으로 미래 목표값을 계산하기 때문에 PoW 공격 표면의 일부다. Bitcoin Core의 `CalculateNextWorkRequired`는 합의 간격과 시간 범위 제한을 통해 리타깃을 제약한다.[^ref-btc-core-pow] Bitcoin Core의 컨텍스트 검증은 median-time-past 및 future-time limit를 포함한 타임스탬프 규칙도 검사한다.[^ref-btc-core-validation]

따라서 타임스탬프 조작은 제한되어 있지만 무의미하지는 않다. 조율된 채굴자 집단은 합의가 허용하는 범위 안에서 블록 타임스탬프에 영향을 줄 수 있다. 이는 측정되는 블록 간격과, 리타깃 기간을 거친 후 난이도 계산에 영향을 줄 수 있다. 실제 공격 질문은 "한 채굴자가 난이도를 마음대로 바꿀 수 있는가"가 아니다. "조율된 집단이 리타깃 입력을 충분히 편향시켜 미래 채굴 조건을 바꿀 수 있는가"가 핵심이다.

메인넷 Bitcoin에서 이는 다음에 의해 제약된다.

- median-time-past 요구사항
- 미래 타임스탬프 상한
- 2016블록 리타깃 간격
- 리타깃 조정 한계
- 타임스탬프가 무효일 때 다른 노드가 거부할 블록을 채굴해야 하는 경제적 비용

### Model 6: SPV and Weak-Client Attacks

백서는 간이 결제 검증(SPV)을 전체 트랜잭션 검증 없이 가장 긴 작업증명 체인에 포함되었는지만 확인하는 방식으로 설명한다.[^ref-btc-wp] 개발자 문서 역시 풀노드 검증과 더 가벼운 보안 모델을 분리한다.[^ref-btc-dev-operating]

약한 클라이언트 위험은 PoW가 실패해서가 아니다. 클라이언트가 검증이나 peer discovery를 너무 많이 타인에게 위임하기 때문이다. 라이트 클라이언트는 모든 블록과 트랜잭션 규칙을 독립적으로 검증하지 못하거나 네트워크 시야가 통제될 경우, 풀노드보다 더 오래 오도될 수 있다.

이로부터 다음 운영 원칙이 나온다.

> confirmation count is stronger when measured by an independently validating full node with a healthy peer view.

## 7. 수학적 또는 경제적 모델

### 따라잡기 확률

Nakamoto는 이중지불 경쟁을 임의보행(random walk)으로 모델링한다.

```text
p = probability honest miners find the next block
q = probability attacker finds the next block
z = honest-chain lead in blocks
```

`p > q`라면, 공격자가 `z`블록 뒤에서 언젠가 따라잡을 확률은 다음과 같다.

```text
q_z = (q / p)^z
```

`p <= q`라면, 이 모델에서 공격자의 최종 따라잡기 확률은 `1`이다.[^ref-btc-wp]

직관은 단순하다.

- confirmation은 `z`를 증가시킨다.
- 공격자 해시파워가 낮을수록 `q / p`가 작아진다.
- `q < p`이면 확률은 지수적으로 감소한다.
- `q >= p`이면 안전한 수준으로 수렴하지 않는다.

### Confirmation 이후의 Poisson 근사

백서는 정직 체인이 `z`개의 블록을 찾는 동안 공격자도 일부 비공개 블록을 찾았을 수 있다는 점을 반영한다. 공격자의 비공개 진척은 기대값이 다음인 Poisson 분포로 모델링된다.

```text
lambda = z * (q / p)
```

이를 통해 트랜잭션이 `z` confirmation을 받은 뒤 공격 성공 확률을 더 실용적으로 추정할 수 있다.[^ref-btc-wp]

이 모델이 유용한 이유는 confirmation 정책이 다음에 따라 달라져야 함을 보여주기 때문이다.

- 트랜잭션 가치
- 상대방 리스크
- 관측된 네트워크 상태
- 추정 공격자 해시파워
- 확률적 settlement risk에 대한 허용치

### 경제적 비용

이중지불 공격자는 기회비용을 부담한다.

```text
expected_attack_cost ~= forgone honest mining revenue
                       + direct operating cost
                       + failed-attack loss
                       + market/reputation impact
                       - recoverable double-spend value
```

이 식은 합의 규칙이 아니라 해석이다. 수학적으로는 최종성이 아니더라도, 높은 confirmation 수가 왜 경제적으로 의미를 가질 수 있는지 설명하는 데 도움을 준다.

### Selfish Mining 수익

Selfish Mining은 "특정 결제를 되돌릴 수 있는가?"에서 "공정한 몫보다 더 많은 수익을 벌 수 있는가?"로 목표를 바꾼다. Eyal과 Sirer는 이 공격을 상대 수익, 블록 withholding, 동률 상황에서의 네트워크 전파를 중심으로 정의한다.[^ref-eyal-sirer]

핵심 변수는 다음과 같다.

| Variable | Meaning |
|---|---|
| attacker hash share | Selfish pool이 블록을 찾을 확률 |
| propagation advantage | 동률 시 정직 채굴자 중 공격자 브랜치를 채택하는 비율 |
| private lead | 공개 브랜치 대비 비공개 브랜치의 길이 우위 |
| stale rate | 살아남지 못한 브랜치에 낭비된 정직 작업량 |
| relative revenue | 최종 수용된 블록 보상 중 공격자 몫 |

따라서 Selfish Mining 위험은 경제적이며 네트워크 민감적이다. 직접적인 이중지불 위험이 낮더라도 마이닝 중앙화 압력은 동시에 존재할 수 있다.

## 8. 보안 가정

### 핵심 가정

Bitcoin PoW 보안은 다음 가정에 의존한다.

1. 관련 시간 구간에서 정직한 채굴자가 어떤 공모 공격자 집단보다 더 큰 유효 블록 생산력을 가진다.
2. 정직한 풀노드는 모든 합의 규칙을 독립적으로 검증한다.
3. 유효한 블록과 트랜잭션이 충분히 넓게 전파되어, 공격자가 주요 참여자의 네트워크 시야를 지속적으로 장악하지 못한다.
4. 채굴자는 경제적으로 유효 블록을 공개하고 가장 큰 작업량의 유효 체인을 연장할 유인을 가진다.
5. 난이도 조정은 갑작스럽거나 임의적인 목표값 조작을 허용하지 않으면서 장기 해시파워를 추적한다.

### 자주 과장되는 가정

| Overstatement | More Precise Statement |
|---|---|
| "6 confirmation이면 final이다." | 6 confirmation은 많은 리스크 프로파일에 충분할 수 있는 관행일 뿐, 결정론적 최종성은 아니다. |
| "51% 공격자는 누구의 코인이든 훔칠 수 있다." | 공격자는 유효 트랜잭션의 순서를 바꾸거나 검열할 수 있지만, 적법한 승인 없이 코인을 쓸 수는 없다. |
| "PoW만 있으면 라이트 클라이언트도 안전하다." | 라이트 클라이언트는 헤더, 피어, 그리고 자신이 보여지는 체인에 대한 가정에 의존한다. |
| "Selfish Mining은 과반 해시파워가 있어야만 가능하다." | Selfish Mining 연구는 전파 가정 아래 과반 미만에서도 수익성 있는 이탈을 다룬다. |
| "reorg는 항상 공격이다." | 작은 reorg는 정상적인 블록 전파 경쟁에서도 발생할 수 있다. |

### 위협 경계

PoW 공격은 기관 손실 시나리오 전부를 설명하지 않는다. 지갑 손상, 개인키 탈취, 수탁 실패, 사회공학, 거래소 지급불능, 브리지 익스플로잇은 Bitcoin 트랜잭션과 주변에서 발생하더라도 PoW 공격이 아니다.

## 9. Bitcoin Core 구현

Bitcoin Core에는 "과반 공격 탐지"나 "Selfish Mining 탐지" 같은 함수는 없다. 구현은 로컬 검증 및 체인 선택 규칙을 강제할 뿐이다.

관련 구현 경계는 다음과 같다.

| Component | Role |
|---|---|
| `CheckProofOfWork` | 헤더 해시가 주장 목표값을 만족하는지 검증한다.[^ref-btc-core-pow] |
| `ContextualCheckBlockHeader` | `nBits`, 타임스탬프, 컨텍스트 기반 헤더 규칙이 올바른지 검사한다.[^ref-btc-core-validation] |
| `CheckBlock` | 전체 블록 구조, 머클 루트, 코인베이스 위치, 트랜잭션 수준 구조를 검증한다.[^ref-btc-core-validation] |
| `AcceptBlockHeader` | 헤더 검증을 알려진 부모와 컨텍스트 검증에 연결한다.[^ref-btc-core-validation] |
| Chainwork accounting | 가장 큰 누적 작업량을 가진 유효 체인을 선택할 수 있게 한다.[^ref-btc-dev-operating] |

공격이 Bitcoin Core에 대해 성공하려면, 공격자는 합의 검증을 통과하면서도 선택 체인이 될 만큼 충분한 누적 작업량을 가진 브랜치를 제시해야 한다. 무효 블록은 여전히 무효다.

따라서 공격 분석은 다음을 분리해야 한다.

- validity: 풀노드가 이 블록을 받아들이는가?
- work: 이 브랜치가 더 많은 누적 작업량을 가졌는가?
- propagation: 누가 어느 브랜치를 먼저 보았는가?
- timing: 상대방은 언제 settlement 결정을 내렸는가?
- visibility: 피해자 노드의 시야는 건강했는가?

### Reorg Handling

Bitcoin Core의 합의 동작은 로컬이며 규칙 기반이다. 노드는 어떤 브랜치가 "정직한지" 판단하지 않는다. 대신 블록을 검증하고, 작업량과 컨텍스트 규칙에 따라 최선의 유효 체인을 추적한다. 더 많은 작업량의 유효 브랜치가 나타나면, reorganization은 정상 프로토콜 동작이다.

이 말은 곧 "attack reorg" 같은 온체인 라벨은 분석가의 해석이라는 뜻이다. 체인 데이터는 reorg 자체는 보여줄 수 있지만, 의도는 추가 증거가 필요하다.

## 10. 온체인 함의

### 관측 가능한 신호

| Signal | Possible Meaning | Evidence Strength |
|---|---|---|
| Reorg depth | 최근 기록이 다른 브랜치로 대체됨 | reorg 자체에는 강함, 의도 판정에는 약함 |
| Stale/orphan block rate | 전파 경쟁 또는 withholding 행위 | 중간 |
| 동일 풀이 반복적으로 경쟁 블록 생성 | 전파 문제 또는 전략적 행위 가능성 | 중간 |
| 지연된 블록 공개 패턴 | withholding 또는 네트워크 이슈 가능성 | 중간~약함 |
| 확인되었다가 제거된 트랜잭션 | 직접적인 settlement 위험 | 해당 트랜잭션에는 강함 |
| 긴 confirmation 간격 | 해시레이트 하락, 네트워크 이슈, 또는 운 | 단독으로는 약함 |
| 비정상적 타임스탬프 패턴 | 채굴자 타임스탬프 행위 | 지속되면 중간 |
| 풀 집중도 | 과반 또는 Selfish Mining 리스크 요인 | 노출도 지표로는 강함, 공격 증거로는 약함 |

### 직접 관측되지 않는 것

다음은 보통 공개 체인 데이터만으로는 직접 보이지 않는다.

- 공개 전의 private fork
- stale block이 우연인지 전략인지
- 채굴자가 특정 트랜잭션을 의도적으로 검열했는지
- 피해자 노드가 Eclipse되었는지
- 풀이 내부적으로 유효 블록을 숨겼는지
- 채굴자의 타임스탬프 선택이 조율된 것인지

### Confirmation Policy

confirmation 정책은 리스크 기반이어야 한다.

| Context | Lower Confirmation Tolerance | Higher Confirmation Requirement |
|---|---|---|
| Transaction value | 작음 | 큼 |
| Counterparty trust | 알려져 있고 저위험 | 미지 또는 적대적 |
| Asset liquidity | 빠른 현금화가 어려움 | 빠른 현금화가 쉬움 |
| Network conditions | 정상 stale rate와 전파 | reorg, 지연, peer 이슈 |
| Node setup | 독립 풀노드 | 제3자 API 또는 약한 클라이언트 |
| Business reversibility | 정산 동결 가능 | 비가역적 인도 |

분석가는 confirmation 수를 최종성의 이진 스위치가 아니라 리스크 입력값으로 다뤄야 한다.

### Reorg 해석 워크플로

reorg가 관측되면 다음을 수행한다.

1. 블록 단위 깊이를 측정한다.
2. 영향받은 트랜잭션을 식별한다.
3. 높이만이 아니라 누적 작업량을 비교한다.
4. 어떤 브랜치가 활성 체인이 되었는지 확인한다.
5. 가능하면 블록 타임스탬프와 도착 시각을 함께 본다.
6. 독립 풀노드 시야를 비교한다.
7. 마이닝 풀 attribution은 신중하게 다룬다.
8. 기계적 합의 결과와 공격 의도를 분리한다.

## 11. 기관 관점에서의 해석

### Settlement Risk

기관은 Bitcoin settlement를 확률적 최종성으로 다뤄야 한다. 실무 질문은 "이게 final인가?"가 아니라 다음이다.

> 이 트랜잭션, 상대방, 금액, 운영 워크플로 기준에서 reversal의 확률과 비용이 수용 가능한가?

고액 입금의 경우 confirmation 임계값은 다음과 함께 운용되어야 한다.

- 독립 풀노드 검증
- 피어 다양성
- reorg 모니터링
- mempool 인지
- 지연 크레딧 또는 단계적 공개
- 대체 시도에 대한 체인 감시
- reorg 이벤트 대응 절차

### Custody and Exchange Controls

PoW 공격 모델은 운영 통제와 맞물린다.

| Control | Reason |
|---|---|
| 독립 풀노드 운영 | 제3자 또는 Eclipse된 체인 시야 회피 |
| 다중 네트워크 경로 사용 | 로컬 고립 리스크 완화 |
| 크레딧 전 reorg 모니터링 | 대체 리스크 포착 |
| 금액별 confirmation 차등 | 확률적 최종성과 노출도 정합 |
| 풀 집중도 추적 | 과반 및 Selfish Mining 리스크 모니터링 |
| 출금 지연 설정 가능하게 유지 | 공격자 현금화 속도 저하 |
| 브랜치 및 stale block 데이터 보존 | 사후 사고 복원력 향상 |

### 피해야 할 분석 실수

다음을 추론하면 안 된다.

- 모든 reorg가 악의적이라는 결론
- 무효 블록이 없었으니 공격도 없었다는 결론
- 과반 해시파워면 서명을 깨뜨릴 수 있다는 결론
- 공개 체인 시야가 모든 피해자의 로컬 시야와 같다는 결론
- stale block이 Selfish Mining의 증거라는 결론
- confirmation 수가 모든 거래 금액에서 동일한 리스크 의미를 가진다는 결론

### Risk Matrix

| Attack | Probability on Bitcoin Mainnet | Impact if Successful | Analyst Confidence From Public Chain Alone |
|---|---|---|---|
| 1블록 우발 reorg | 낮지만 정상 범주 | 대체로 낮음 | 높음 |
| 깊은 이중지불 reorg | 정상 해시 분포에서는 매우 낮음 | 피해 상대방에게 큼 | 공개 후 높음 |
| 지속적 과반 검열 | 정상 해시 분포에서는 매우 낮음 | 매우 큼 | 중간 |
| Selfish Mining | 모델 의존적 | 시간이 지나며 중간~높음 | 낮음~중간 |
| 기관 대상 Eclipse | 인프라 의존적 | 피해자에게 큼 | 로그 없이는 낮음 |
| 난이도 조작 | 정상 메인넷에서는 매우 낮음 | 지속되면 중간~높음 | 중간 |

확률 라벨은 정성적이다. 현재 해시레이트 분포, 마이닝 풀 집중도, 네트워크 건강도, 사업 노출도에 맞춰 갱신해야 한다.

## 12. 흔한 오해

### Misconception 1: A 51% attacker can do anything.

틀렸다. 과반 공격자는 충분한 작업량으로 순서 통제와 검열은 할 수 있지만, 풀노드는 여전히 무효 트랜잭션과 무효 블록을 거부한다.[^ref-btc-wp][^ref-btc-core-validation]

### Misconception 2: A double spend requires invalid signatures.

틀렸다. 이중지불 reorg는 동일한 코인에 대한 두 개의 충돌하는 유효 지출을 사용한다. 어떤 지출이 수용된 역사에 남는지는 winning chain이 결정한다.

### Misconception 3: Confirmations create deterministic finality.

틀렸다. confirmation은 공격자 해시파워가 정직한 채굴자보다 작을 때, 역전 비용을 높이고 통계적 성공 확률을 낮춘다.[^ref-btc-wp]

### Misconception 4: Selfish mining is the same as a 51% attack.

틀렸다. Selfish Mining은 전략적 블록 withholding과 수익 공격이며, Eyal과 Sirer가 연구한 모델에서는 과반 미만에서도 수익성이 있을 수 있다.[^ref-eyal-sirer]

### Misconception 5: Eclipse attacks are visible as a special on-chain marker.

틀렸다. Eclipse 공격은 피해자의 네트워크 시야를 조작한다. 공개 체인은 정상처럼 보여도 피해자는 고립되어 있을 수 있다.[^ref-heilman-eclipse]

## 13. Analyst Checklist

어떤 이벤트를 PoW 공격으로 분류하기 전에 다음을 점검하라.

1. 실제로 reorg가 발생했는가?
2. reorg 깊이는 얼마인가?
3. 어떤 트랜잭션이 제거, 대체, 신규 confirmation 되었는가?
4. 대체 브랜치가 더 큰 누적 작업량을 가졌는가?
5. 모든 블록이 합의 규칙상 유효했는가?
6. 블록 공개가 지연되었거나 비정상적으로 몰려 있었는가?
7. 경쟁 브랜치에 알려진 풀이 관여했는가?
8. 영향받은 상대방은 제3자 API를 썼는가, 아니면 자기 풀노드를 썼는가?
9. peer 연결 로그, 노드 로그, 블록 도착 시각 데이터가 있었는가?
10. 기계적 체인 결과를 넘어서는 의도 증거가 있는가?

이중지불 리스크에 대해서는 다음을 묻는다.

1. 뒤집힌 거래 금액이 공격자에게 경제적 동기를 줄 만큼 컸는가?
2. 충분한 confirmation 전에 크레딧이 이루어졌는가?
3. 피해자가 더 넓은 네트워크로부터 고립되어 있었는가?
4. reorg 전에 충돌 지출이 보였는가?
5. 공격자의 기대 이익이 실패 위험과 채굴 비용보다 컸는가?

Selfish Mining 리스크에 대해서는 다음을 묻는다.

1. stale block 비율이 기준선을 넘어서 상승했는가?
2. stale block이 특정 풀 또는 지역에 집중되는가?
3. 경쟁 공개 블록 직후 의심스러운 타이밍의 블록 공개가 있는가?
4. 독립 릴레이 네트워크 데이터가 있는가?
5. 단순한 네트워크 지연만으로도 이 패턴을 설명할 수 있는가?
